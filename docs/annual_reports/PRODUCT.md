# 年报分析助手：产品说明与验收口径

## 产品定位

面向金融专业学生和初级研究者，把同一家公司两期中文年报整理为**可以逐项核对、追溯出处和导出的财务分析底稿**。

第一版解决的具体任务是：找到关键数字，辨认年度与单位，检查两期是否可比，再解释已经有证据支持的变化。用户仍负责复核和判断。目标用户和需求目前是产品假设，尚未通过规模化访谈或用户实验验证。

这次新增的是场景应用：年报 PDF 提取、候选数据复核、可比计算、原文查看、本地检索、模型发送预览和底稿导出。通过 `oh reports` 进入专用应用，模型配置与凭据解析复用项目已有能力。

应用实际接入了 OpenHarness 的原生工具体系：年报查询、原文页读取和比较结果分别实现为三个 `BaseTool`，经 `ToolRegistry` 注册，使用 Pydantic 校验参数，再通过 `PermissionChecker` 的 PLAN 只读检查，在 `ToolExecutionContext` 中执行，并返回包含来源信息的 `ToolResult`。这些调用已接入实际服务路由；没有加载通用 Shell、任意文件读取或联网工具。当前模型解读是用户批准后的单次固定请求，不是模型自主选择工具的循环。

**状态说明：第一版本地集成与公开样本验收已完成。具体结果、样本范围和限制见 [验收记录](EVALUATION.md)。产品需求与用户效率收益仍需通过真实使用验证。**

## 用户任务与完成条件

典型任务：上传同一家公司相邻年度的两份年报，核对营业收入、归母净利润等数据，形成两期对照表，回答有依据的财务问题，并把底稿交给自己或他人复查。

完成条件不是“生成了一段看起来专业的分析”，而是：

1. 每个参与计算的数字都有明确年度、金额单位、币种、合并范围、文件和 PDF 页码。
2. 自动提取值经过人工复核；缺失和不确定值没有被当作零或已确认事实。
3. 比较使用相邻年度及可比口径；增长率由程序计算。
4. 对照表、来源证据和复核状态能一起导出。
5. 使用外部模型前，用户知道将发送什么，并作出明确选择。

## 第一版范围

输入以可以提取文字的中文上市公司年度报告 PDF 为主。扫描件、复杂跨页或多层重述表格可能无法可靠识别，应该提示用户补充文本型文件或人工核对，不能把未识别内容解释成没有披露。

优先提取“主要会计数据”等合并口径表格，金额保留原始单位与原文；PDF 物理页码从文件第一页开始计数，可能与页脚印刷页码不同。

| 指标 | 明确口径 | 用途 |
| --- | --- | --- |
| 营业收入 | 合并口径的营业收入 | 观察业务规模变化 |
| 归母净利润 | 归属于上市公司股东的净利润 | 观察归属于母公司股东的盈利变化 |
| 扣非归母净利润 | 扣除非经常性损益后的归母净利润 | 与归母净利润对照，保留两者的差异 |
| 经营现金流净额 | 经营活动产生的现金流量净额 | 与盈利变化并列观察 |
| 总资产 | 合并资产总额 | 观察期末资产规模 |
| 归母净资产 | 归属于上市公司股东的净资产或权益 | 观察期末权益规模 |

第一版不自动完成投资评级、目标价、审计判断或经营变化归因。金融行业及特殊格式报告的适配情况要单独验证，不能由一个演示公司外推。

## 用户流程

1. **载入资料。** 上传 PDF，或者载入附有公开来源的演示年报。本地提取文字、识别公司和年度，保留原始文件及摘要标识。
2. **浏览候选。** 六类指标按本期和上期列出。自动提取结果统一标记为待核对，不预先展示为已确认业绩。
3. **逐项复核。** 点击数值查看本地渲染的 PDF 源页图像与提取文字，也可打开原 PDF，核对金额、单位、币种及合并口径；有误可以修正，再确认。缺失项需要有来源才能补录。
4. **查看比较。** 满足可比条件的已确认数字转换为人民币元，由 Decimal 完成金额差额和同比计算。其他行保持待核对或缺失状态。
5. **提问与检索。** 指标和同比类问题优先用本地确定性结果回答；原因及披露类问题先返回相关原文片段，缺少依据时说明不足。
6. **可选模型解读。** 查看准确的发送预览，确认后才发送给 DeepSeek。预览与当前资料、复核状态绑定，有效期十分钟且只能使用一次；发送前检查版本，变更后需要重新预览。模型输出与已核对事实分开呈现，不自动覆盖数字。
7. **导出与清理。** 下载对照表或 Markdown 底稿，保留来源、单位和复核状态；可删除导入资料及对应本地数据。

## 数据状态与计算规则

| 状态 | 展示方式 | 能否计算 |
| --- | --- | --- |
| 自动候选 | 展示金额和来源，提示待核对 | 不参与正式计算 |
| 人工确认 | 保留来源，并记录修正后的值 | 还须检查单位、币种、合并口径和页码 |
| 缺失 | 明确显示缺失，不以零填充 | 不计算 |
| 口径不清或多候选冲突 | 展示核对提示 | 处理歧义后才能计算 |

- 金额单位支持元、千元、万元、百万元、亿元；当前不自动换汇。
- 同比为 `(本期 - 上期) / 上期 × 100%`。上期为零或负数时，不给出容易误解的常规增长率，仍可列出金额变化。
- 优先使用较新年报同表披露的上期可比数。若与上一年原始披露值不同，提示核对调整、重述或提取差异。
- 较新年报的可比期尚未确认时，不悄悄换用已确认的旧披露数。
- 母公司报表数值不能直接混入合并口径比较；币种或单位不清时暂停计算。
- 两份文件公司不同、报告年度相同或不相邻时，明确阻止同比比较。
- “经营现金流净额 / 归母净利润”仅作为明确标注口径的观察比例，不能单独推导盈利质量。

## 产品取舍

**先做可核对流程。** 通用对话很灵活，但用户还需要处理年份、单位、出处和导出。第一版把这些步骤固定下来，使错误可以被发现。它能否节省实际工作量，需要用用户任务验证。

**保留人工复核。** 数字错误会被计算和文字解读放大。复核增加操作时间，换来用户在进入分析前检查证据的机会。后续优化应测量复核负担，而不是把“确认过”视为准确性的充分证明。

**计算与解读分开。** 同比和金额转换使用确定性代码；模型用于解读证据。经营原因仍需原文依据，不能从相关指标自动推导因果关系。

**先覆盖少量明确指标。** 六个指标的年度和口径可以集中核验，便于建立评测集。扩大指标数量前，应先验证不同公司的格式和重述处理。

**本地处理与外发明确分界。** 提取、复核、比较和本地检索默认不需要外部模型。可选模型请求通过精确预览和明确确认控制。这个边界只描述专用应用流程，不能推广成整个项目所有 Agent、插件和命令均已受完整隔离。

**复用工具执行规范，限制自主程度。** 三个只读工具沿用统一的参数、权限、上下文与结果契约，避免各个页面绕开执行检查。涉及上传、复核和删除的写操作仍由服务接口和资料存储层独立校验；模型不能自行发起这些操作。这一版先采用明确步骤的工作流，便于检查金融数据处理过程。

## 技术接入与实际使用位置

| 能力 | 实际接入位置 | 用户价值与边界 |
| --- | --- | --- |
| `oh reports` | 项目命令入口启动本地 HTTP 服务 | 在原项目中直接进入年报应用 |
| `annual_report_search` | 本地问答和模型预览前的原文检索 | 只处理已导入资料，保留来源 |
| `annual_report_page` | 查看原文页 | 参数只接受报告 ID 和页码，不接收任意路径 |
| `annual_report_compare` | 工作区状态、模型预览和导出所用比较结果 | 候选与已确认状态由同一套规则判断 |
| 原生工具执行链 | schema → Pydantic → PLAN 权限检查 → 执行上下文 → 标准工具结果 | 在运行路径中复用框架能力，不声称完整自主调用循环 |
| 已有模型配置与凭据解析 | DeepSeek 服务配置和服务端鉴权 | 密钥不放进浏览器或发送预览；配置存在仍不等于实时请求可用 |
| Decimal 计算 | 年度、单位与口径明确的确认值 | 确定性金额转换和同比，不让模型口算 |
| 预览版本与引用检查 | 可选云端解读 | 固定请求内容、一次性批准、过期失效；引用编号合法不等于语义正确 |

更完整的调用图和代码位置见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 数据边界

- 用户明确上传的 PDF、提取文字、候选值与复核结果存放在本地应用数据目录。
- 资料保存在本地不等于已经加密。设备、备份、共享目录和本机账户仍需保护。
- 默认本地提取和计算不发送模型请求。明确批准后，预览里的证据和问题才会发送给所选模型服务。
- 模型请求仅连接 DeepSeek 官方 HTTPS 接口，不跟随重定向。返回内容中识别到的规范引用编号必须属于本次提供的来源集合；没有引用会提示用户进一步核对。这项检查不证明每句解释均得到原文支持。
- 外部模型的留存和使用规则取决于服务协议与账户配置，不能用界面上的“本地”标签代替审查。
- 本应用不提供“绝不泄漏”、完整敏感信息识别或企业级安全审计保证。
- 本版没有自定义训练、完整 DLP、语义向量检索、模型自主工具循环或自动 Shell 执行；本地检索采用规则和关键词匹配。

## 验收矩阵

| 类别 | 最小验证内容 | 通过依据 |
| --- | --- | --- |
| 提取 | 真实中文年报、跨行标签、金额单位、年份 | 与人工核对的源页和原始披露值一致 |
| 复核 | 候选确认、修正、缺失补录 | 未确认数据不进入计算；修改有来源 |
| 计算 | 不同单位、负数、零基数、缺失 | Decimal 结果符合定义，没有把缺失当零 |
| 可比性 | 公司、币种、年度、合并范围、重述 | 不兼容输入被阻止；优先规则与提示一致 |
| 来源 | 数字、页码、原文、导出 | 能从底稿返回同一文件和证据页 |
| 问答 | 使用说明、指标、同比、原因、无证据 | 简单问题直接答；无依据不补写事实 |
| 模型边界 | 未批准、预览后修改资料、批准发送 | 未批准不请求；批准后只发送预览内容 |
| 本地服务 | 错误文件、超限输入、跨来源请求 | 有明确错误；不能借接口访问任意本地文件 |
| 界面 | 上传、核对、来源、提问、导出、删除 | 端到端操作完成且状态一致 |

## 指标定义与记录方式

所有数字必须由实际测试产生。演示数据的表现不能称为全市场准确率，自动化测试数量也不能称为用户满意度。

| 指标 | 定义 | 当前记录要求 |
| --- | --- | --- |
| 候选指标覆盖率 | 找到候选的必需字段数 / 人工标注的必需字段数 | 同时记录缺失与歧义，按公司与格式分组 |
| 候选提取正确率 | 年度、金额、单位、币种、范围、来源均匹配的候选数 / 候选总数 | 基于独立人工标注；按原始披露精度核对 |
| 来源一致率 | 确实支持所示数值或说法的引用数 / 引用总数 | 页码必须能打开，片段必须来自原文 |
| 可比计算通过率 | 结果与人工基准一致的可比用例数 / 可比用例总数 | 包含异常和拒绝计算用例 |
| 完整任务完成率 | 形成可核对底稿并正确导出的任务数 / 测试任务数 | 区分自己测试、同学试用和真实用户 |
| 人工复核时间 | 从候选出现到用户确认结束的用时 | 需要真实操作计时，暂不承诺节省比例 |
| 未授权外发次数 | 无明确批准仍发出模型请求的次数 | 在指定测试条件下验证，不能替代安全审计 |
| 模型调用耗时与用量 | 实际请求的耗时、输入输出 token | 没有账单对照时不宣称精确金额成本 |

建议每条评测记录包含：用例 ID、分类、源文件 SHA-256、人工标准值、允许的证据页、预期行为、实际行为、通过状态、耗时和备注。真实年报基准应由独立核对形成，避免拿提取程序自己的输出当标准答案。

## 后续验证顺序

1. 完成第一版集成验收，并保存公开演示年报的来源与人工基准。
2. 增加不同公司、单位和表格格式的真实年报，记录失败类型。
3. 邀请目标用户完成同一任务，观察复核与查证的操作负担。
4. 对照手工查阅或现有工具的真实过程，测量是否节省时间以及纠错成本。
5. 根据证据决定扩展表格格式、OCR、更多指标或其他工作流。
